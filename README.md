# GARNT TOOL REJOIN — English Guide

An automatic Roblox rejoin tool for UG Phone + Termux (for use with your own accounts and devices only).

## Related files

| File | Purpose |
|---|---|
| `rejoin.py` | The main program (single file) |
| `setup.sh` | One-command installer |
| `requirements.txt` | Python libraries (`rich`, `requests`) |
| `/sdcard/Download/RejoinTool/config.json` | Settings (contains no cookies) |
| `/sdcard/Download/RejoinTool/cookie.txt` | Cookies, 1 line / 1 account (optional) |
| `/sdcard/Download/RejoinTool/logs/` | Daily logs, kept for 7 days |
| `/sdcard/Download/RejoinTool/heartbeat/` | `.lua` scripts generated by the menu for each instance (single example: `heartbeat.lua`) |
| `/sdcard/Download/RejoinTool/screenshots/` | Screenshots, latest 20 kept (root only) |

## 1. Installation (follow in order)

### Step 1 — Choose a Termux mirror
```
termux-change-repo
```
Move with the arrow keys, press Space to select "Single mirror" (or Mirror group) → choose a nearby mirror (e.g. Singapore / Asia) → OK.
If you skip this and `pkg update` is slow or gives a 404 error, come back and do it again.

### Step 2 — Install with one command
```
curl -Ls https://raw.githubusercontent.com/Garnt024020806/TOOL/main/setup.sh | bash
```
The script does the following in order: `termux-setup-storage` → `pkg update/upgrade` → `python`, `python-pip`, `tsu`, `libexpat`, `openssl` → `pip install -r requirements.txt` → downloads `rejoin.py` to `/sdcard/Download/rejoin.py` (with a copy at `~/rejoin.py`).

- The storage permission prompt pops up right at the start → tap **Allow** quickly (before the script reaches the file download line). If you were too slow, just run the install command again.
- If `pkg upgrade` asks anything, the script answers yes for you. Wait until it finishes.

### Step 3 — Set Android / Termux permissions and how to verify them

| Permission | How to set | How to verify |
|---|---|---|
| Storage | Settings > Apps > Termux > Permissions > Files and media / Storage = Allow (or run `termux-setup-storage`) | `touch /sdcard/Download/t && rm /sdcard/Download/t` must produce no error |
| Disable battery saving | Settings > Apps > Termux > Battery = **Unrestricted / Not optimized** (do the same for every cloned Roblox app) | In Settings > Battery > Optimization, Termux/Roblox must not be in the restricted list |
| Root permission | Enable root on the UG Phone, run `su` once, and tap **Grant/Allow** for Termux in the root manager app (Magisk/KernelSU) | `su -c id` must show `uid=0(root)` |
| Display over other apps (non-root mode) | Settings > Apps > Termux > Display over other apps = Allow | Without it, Termux cannot launch the game in non-root mode |
| Keep Termux in recents | Pull down the Termux notification and tap "Acquire wakelock", or let the program do it (Automation settings > Wake-lock) | The Termux notification shows "wake lock held" |

### Step 4 — Run the program (root mode)
```
su -c "export PATH=$PATH:/data/data/com.termux/files/usr/bin && export TERM=xterm-256color && cd /storage/emulated/0/Download && python ./rejoin.py"
```
Non-root mode (or running from `~`):
```
cd ~ && python rejoin.py
```
The program detects the mode itself with `su -c id` — you don't need to tell it which way you are running.

## 2. How to use

1. Menu **3**: set the game link (supports Place ID, `roblox.com/games/...`, private server links, share links, `roblox://...`) and adjust the check interval / launch delay.
2. Menu **4**: scan for `com.roblox.*` packages and choose which to run (`1,3` or `all`).
3. (Optional) Menu **5**: put cookies in `cookie.txt` and log in.
4. Menu **6**: adjust automation. Menu **7**: set the Discord webhook.
5. Menu **1**: start rejoining — press `Ctrl+C` to stop and return to the menu.

### Core behavior
- Instances are launched one at a time, 15 seconds apart (both at startup and when rejoining mid-run).
- It checks every 30 seconds — after a drop it waits 10s → 20s → 40s … up to 300s before rejoining, and resets after 5 minutes of continuous stability.
- After launching the app there is a 90-second join grace period (adjustable in Menu 6); a drop is not counted during this time.

### Root vs. non-root
| Capability | Root | Non-root |
|---|---|---|
| Check the app process | ✅ | ⚠️ Not possible on most devices |
| Check the app is in the foreground | ✅ (off by default) | ❌ |
| Force-stop before relaunching | ✅ | ❌ |
| Screenshots / attach to webhook | ✅ | ❌ |
| Inject cookies into the app | ✅ | ❌ (cookies can still be validated) |
| Check "in game" via Roblox API | ✅ if cookies are provided | ✅ if cookies are provided |

Non-root mode without cookies shows "Unknown" status — use Menu 6 "Timed rejoin (minutes)" instead.

### Auto-generate heartbeat.lua into Delta's autoexec folder
The tool creates/updates `heartbeat.lua` in `/storage/emulated/0/Delta/Autoexecute/` automatically every time the program opens, every time you start rejoining, and whenever you change the heartbeat port/frequency. No need to copy the file yourself.
- Other files in the folder (e.g. `BSS.lua`) are not touched, and if a `heartbeat.lua` that isn't the tool's own already exists, it is skipped and not overwritten.
- The first time the file is created successfully, heartbeat is enabled once for you (you can turn it off later at Menu 6 > Heartbeat > 1 and it will not be re-enabled).
- You can change the folder, toggle auto-creation, or create immediately at Menu 6 > Heartbeat, items 6, 7, 8 (put `{pkg}` in the path if each clone has its own autoexec folder; it will create one per clone).
- A single file works for multiple clones that share a folder: in root mode, the tool determines which app (UID) a signal came from via `/proc/net/tcp` and matches it to the package itself. If that can't be read, it matches to the only running instance, or matches by account name when cookies are available.
- Reopen the game once after the file is created so Delta runs the script when you join.

### Heartbeat (in-game script)
A Lua script running in the game sends a signal to the tool (`127.0.0.1`, on the device itself) every 15 seconds, so the tool knows an instance is "really playing" without needing root or cookies. The script **stops sending** when the game frame has been frozen for more than 5 seconds or when a Disconnected/Error window appears.

Setup:
1. Menu 6 > Heartbeat > press 5 to generate a `.lua` file per instance (each file has `ID` already set to that clone's package name).
2. Copy each clone's file into that clone's executor autoexec folder, or run it when you join the game.
3. Menu 6 > Heartbeat > press 1 to enable it, then start rejoining from Menu 1.

Behavior: if it is silent for more than 90 seconds (adjustable), or there is no signal after the join grace period following a rejoin, it rejoins with the usual backoff. If a signal has never been received from an instance, the tool falls back to the old detection method (without rejoin loops) and shows this in "Details".

Notes: you need an executor that can make HTTP calls to `127.0.0.1`, and using an executor violates Roblox's rules and may get your account banned — the decision and risk are yours. You can test the receiver with `curl http://127.0.0.1:8765/ping` (it must reply `pong` while rejoining is running).

### Live panel + rejoin console (Menu 1)
While running, the live panel shows per-instance status (state, time played, fails/rejoins, next check time, details) along with free RAM and device load. Recent events are listed below (newest on top), and there is a **Console** field where you can type a command and press Enter immediately.

| Command | What it does |
|---|---|
| `rejoin 1` / `rejoin all` | Force an immediate rejoin (root: force-stop first), skips backoff and is not counted as a failure (short form: `r`) |
| `pause 1` / `pause all` | Temporarily stop looking after the instance (short form: `p`) |
| `resume 1` / `resume all` | Resume looking after it and rejoin immediately |
| `status` | Summarize the status of every instance |
| `ram` | Clear RAM now (root) |
| `shot` | Take a screenshot, save it in the folder, and send a report to the webhook if set (root) |
| `clear` | Force-clear stacked screens (root) |
| `help` / `quit` | Show commands / stop and return to the menu (or press Ctrl+C) |

The instance number is the number in the `#` column, which matches Menu 2 and the cookie order. Menu **2** is also a live panel that auto-refreshes (press Enter to go back).

### Console webhook (Menu 7)
Sends every console line (events, typed commands, results) to Discord as code-block messages, batched every 10 seconds (adjustable 3–300). You can set a URL separate from the main webhook; if left blank, the main URL is used. Off by default. Values in `config.json`: `console_webhook.enabled/url/flush_sec`.
Note: a Discord webhook can only send messages out; you cannot command the tool from Discord (that would require a bot). Use the console field in the live panel instead.

### Disconnected / Error Code 277 (dropped but no rejoin)
Roblox draws the Disconnected window inside the game itself, so Android sees the app as still running normally — older versions without cookies/heartbeat therefore reported "OK" even though the player had been dropped. This version detects drops in 3 ways (they can be used together):
1. **Screenshot detection (root, on by default)** — takes a raw screenshot and looks for a dark gray rectangular panel (#393B3D) containing a white button. Checks every 30 seconds and must see it 2 rounds in a row before rejoining (to avoid false detections). Configure at Menu 6 > Screen.
2. **Heartbeat** — the in-game script sends an error message (e.g. Error Code 277) as soon as the window appears (use the latest `.lua` file; regenerate at Menu 6 > Heartbeat > 5).
3. **Cookies + Roblox API** — status changes from in-game to offline. Works in both root and non-root mode.

Limitations: method 1 can only see the instance that is on screen (the focused window). If you run multiple clones, combine it with method 2 or 3. If Roblox's window style changes and detection fails, try Menu 6 > Screen > 8 (test Disconnected detection now — does nothing) while the window is showing.

### Clear stacked screens (Menu 6 > Screen)
Checks every 60 seconds (root only): dismisses stuck system windows, force-stops apps showing a "has stopped / not responding" window so the system rejoin can reopen them, and force-stops clones that have duplicate stacked tasks (must be detected 2 rounds in a row, with a 10-minute gap per app). The "Close stray apps overlaying the screen" option is off by default (except Termux/system/home/Magisk). If it force-stops healthy clones when it shouldn't, turn off "force-stop apps with stacked windows". Use item 9 to see what it detects first, and item 10 to clear immediately.

### Clear RAM / reduce CPU usage / status reports (Menu 6 > Performance, Menu 7)
**Clear RAM (root only)** — clears the memory cache (`drop_caches`) every 30 minutes and/or when free RAM drops below 300 MB (at least 1 minute apart). Free RAM is shown on the status panel. The `am kill-all` option is off by default because it may close clones running in the background.

**Reduce CPU usage (on by default)**
- Checks all instances at once on a single schedule and uses a single shell command per round (process list + screen) instead of calling per instance.
- Lowers the tool's process priority (`nice 10`) so the game gets CPU first (takes effect when the program starts).
- Caches Roblox API game-status results for 60 seconds and refreshes the status panel every 2 seconds (adjustable).
- Enables "Check that the app is in the foreground" only when needed, because `dumpsys` uses the most CPU.

**Status report + screenshot to Discord every 10 minutes** — Menu 7 sets the number of minutes (0 = off) and the "status report" switch. Screenshots can only be attached in root mode (non-root sends text only). The latest 20 screenshots are kept in the `screenshots/` folder.

Values in `config.json`: `webhook.periodic_min` (10), `ram.interval_min` (30), `ram.min_free_mb` (300), `ram.kill_cached` (false), `performance.low_cpu` (true), `performance.ui_refresh_sec` (2)

### About cookies (cookie.txt)
- 1 line / 1 account, matched to the detected instances in order (first line = first package). Blank lines and lines starting with `#` are skipped.
- The program always displays cookies masked, never writes them to logs, never sends them to the webhook, and never stores them in `config.json`.
- **Never share this file or pass it to anyone** — whoever gets the cookie can access your account immediately.
- Injecting cookies writes into the app's cookie database (`app_webview/.../Cookies`) and depends on the Roblox/clone version. If it doesn't succeed, log in inside the app by hand once.

## 3. Troubleshooting common problems

| Symptom | Fix |
|---|---|
| `ModuleNotFoundError: rich` / `requests` | `pip install -r requirements.txt` (if it still isn't found when running via `su`, install from normal Termux, not inside su) |
| `CANNOT LINK EXECUTABLE` or `libpython... not found` when running via `su` | Add `export LD_LIBRARY_PATH=/data/data/com.termux/files/usr/lib &&` before `cd ...` in the command |
| `python: not found` in `su` | Check that the command contains `export PATH=$PATH:/data/data/com.termux/files/usr/bin` |
| Program says "non-root" even though you have root | Run `su -c id` yourself in Termux and tap Grant in the root app; if it doesn't show `uid=0`, permission hasn't been granted yet |
| "Cannot write /sdcard/Download" | Allow storage permission for Termux, then run `termux-setup-storage` again |
| Package not found | In Menu 4, type the package names yourself (comma-separated) or edit `package_prefix` in `config.json` |
| App opens but doesn't join the game (shows "used launcher instead") | The link isn't being passed to the cloned app. Try a plain Place ID, or a `roblox://placeID=...` link |
| Rejoins in a loop even though in game | Turn off "Check that the app is in the foreground" (Menu 6) when running multiple instances at once — only one app can be in the foreground |
| Cookie "expired/invalid" | Log in on the web again and copy a new `.ROBLOSECURITY` (logging out invalidates the old cookie) |
| heartbeat.lua not visible in the Delta folder | Menu 6 > Heartbeat > 8 to see the result (created/skipped/error) and check that Termux has storage permission |
| Heartbeat not arriving (details show "no heartbeat yet") | Check that `ID` in the script matches the package name, the port matches Menu 6 > Heartbeat, the executor allows HTTP to localhost, and that Menu 1 has been started (the receiver is only open while rejoining is running) |
| Status report doesn't arrive every 10 minutes | Menu 7: enable the Webhook, enable "status report", set minutes > 0, and Menu 1 must be running (the first report arrives after the full number of minutes has passed since start) |
| Can't clear RAM | Requires root; try Menu 6 > Performance > 7 to see the result immediately |
| Disconnected (Error 277) shows but no rejoin | Must be root mode + Menu 6 > Screen item 1 enabled. Use item 8 to test while the window is showing. If it says "Cannot detect", the raw screenshot can't be read — use heartbeat or cookies instead; with multiple clones you must also use heartbeat/cookies |
| Menu screen is duplicated / garbled | v1.4 changed how the screen is cleared. If it still happens, close and reopen Termux and use the run command with `export TERM=xterm-256color` |
| Typing a console command does nothing | Must run from a real Termux terminal (not a pipe). Type `help` and press Enter and look at the events box |
| Webhook doesn't send | Menu 7 > 8 sends a test; the URL must start with `https://discord.com/api/webhooks/` |
| Characters are garbled on screen | Set `export TERM=xterm-256color` and use a font in Termux that supports the characters shown |
| See what happened earlier | Open `/sdcard/Download/RejoinTool/logs/rejoin.log` |
